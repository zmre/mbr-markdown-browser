## Project Overview

**mbr** (markdown browser) is a Rust application that serves as a markdown previewer, browser, and static site generator. It renders markdown files on-the-fly via a local web server, supports navigation between markdown files, browsing by tags/folders, and searching. The key principle is that any markdown repository can customize its UI via a `.mbr/` folder.

## Code Quality (MANDATORY)

Before completing ANY Rust code changes, you MUST run these checks:

```bash
# Format all Rust code (every crate in the workspace)
cargo fmt --all

# Sort Cargo.toml dependency tables (every manifest in the workspace).
# Always these flags: they are what CI (`nix build .#cargo-sort`) checks.
cargo sort --workspace --grouped --no-format

# Check for lint issues (warnings are errors)
# IMPORTANT: Use --all-targets to check test code too (matches CI)
cargo clippy --workspace --all-targets -- -D warnings

# Run tests
cargo test --workspace
```

**These are blocking requirements.** Do not consider Rust work complete until:
1. `cargo fmt --all` has been run (code is formatted)
2. `cargo sort --workspace --grouped --no-format --check` passes (manifests are sorted). `--grouped` sorts within blank-line groups, so a comment heading a group stays with it — put a new dependency in the group it belongs to. `.tomlfmt.toml` sets the table order; it is what keeps `[workspace]` the first table of the root `Cargo.toml` (see Workspace Crates: bump-version.sh reads the first `^version = ` line). `cargo-sort` is in the dev shell
3. `cargo clippy --workspace --all-targets -- -D warnings` passes with no errors
4. `cargo test --workspace` passes

The workspace's `default-members` are all of its crates, so the plain `cargo fmt`/`clippy`/`test` cover them too; `--all`/`--workspace` makes it explicit, and is what CI and the flake pass.

CI will reject any PR that fails these checks. The pre-commit hook enforces this locally, but you should run these explicitly to catch issues early.

**Why `--all-targets`?** Without this flag, clippy skips `#[cfg(test)]` code. CI runs with `--all-targets`, so you must too to catch all lints locally.

**When you touch feature gating** (a `#[cfg(feature = …)]`, an optional dependency, a module that moves between subsystems), also lint the non-default sets — CI builds them all, and an unused import under one set is an error there:

```bash
cargo clippy --workspace --all-targets --no-default-features -- -D warnings                 # every crate, no optional features
cargo clippy -p mbr-core --all-targets -- -D warnings                                       # render core alone
cargo clippy -p mbr-ffi --all-targets -- -D warnings                                        # QuickLook staticlib (macOS)
cargo clippy --workspace --all-targets --no-default-features --features gui,server,watcher,ssg,cli -- -D warnings  # Windows set
cargo check -p mbr-server --all-targets                                                     # server without the watcher
```

Where a doc goes (`docs/` is organized by what the reader is doing):
- `docs/markdown/` — **syntax only**: what a reader types (frontmatter, links, tasks, agenda entries, math, sections, media, chat…). One page per construct; `markdown/index.md` is the at-a-glance table, so add a row there too.
- `docs/features/` — what mbr **does** with notes (browsing, search, links, calendar, task browser, slides, flashcards, contacts, editing, review…). Each page starts with a `**Works in:**` line and links to its syntax page rather than restating it; `features/index.md` holds the "where each feature works" matrix.
- `docs/modes/` — how mbr runs (GUI, server, build, QuickLook, iOS). `docs/reference/` — look-up material (CLI, configuration, shortcuts, `http-api.md` for endpoints, architecture, development, `ios-development.md`).
- Sidebar order is the `order:` frontmatter field. `tests/docs_anchors.rs` fails on any `#fragment` link in `docs/` that lands nowhere, so run it after moving or renaming a heading. The iOS app bundles `docs/` as its sample vault, and its self-test loads `/features/flashcards/`.

### Test Updates

Add or update tests when:
- Adding new functions (add unit tests in the same file)
- Adding new CLI options (add integration tests)
- Fixing bugs (add regression tests to prevent recurrence)
- Changing behavior of existing functions (update existing tests)

**Test locations:**
- Unit tests: In the same `.rs` file under `#[cfg(test)] mod tests`
- Integration tests: `tests/server_integration.rs` for HTTP/server behavior
- Build tests: `tests/build_integration.rs` for static site generation
- Property tests: Use `proptest` for invariant verification

**New markdown syntax needs the editor too (parity harness).** The in-browser editor re-serializes what it loads, so a construct the renderer understands and the editor does not is rewritten on save. When you add or change syntax in the renderer (`markdown.rs`, pulldown-cmark options): add a fixture `tests/fixtures/editor-roundtrip/<name>.md`, regenerate its renderer outline (`MBR_UPDATE_OUTLINES=1 cargo test -p mbr-core editor_parity`, then review the `.outline.json`), and give the editor a plugin in `components/src/editor-plugins/` (or an opaque node that prints its source verbatim) registered in `MARKDOWN_EXTENSION_PLUGINS`. `components/src/editor-parity.test.ts` holds every fixture to a byte-identical untouched save and to the renderer's block outline; a fixture that cannot pass yet goes in its `ROUND_TRIP_FAILS`/`OUTLINE_FAILS` with the reason.

## Goals



- **Speed** - Sub-second rendering, instant navigation, fast site builds.
  - In this tool, **performance is extremely important** -- for launch of GUI and server, render of a markdown, build of a site, and for built sites, loading and rendering in a browser.  Everything should be near instantaneous and we should be constantly looking for safe ways to make things fast, but without using local cache files (one exception, **mobile only**: the iOS app keeps its index snapshot in its own sandboxed `Caches/` directory — never on the desktop, never in the notes folder; see [Mobile core](#mobile-core-mbr-ffi-mobile)).  This tool may be used on repositories with tens of thousands of markdown files and as many assets (images, pdfs, etc.) as well and it MUST perform well even on big repositories. Anything slow must be async and background and out of the critical path. It should also be made as fast as possible.
- **No lock-in** - Works with any markdown repository without modifications to the markdown files
- **Customizable** - Override styles, templates, and components per-repository
- **Rich content** - Embed videos, audio, PDFs, diagrams, and more with native markdown image syntax that works magically with other media types
- **Zero run-time dependencies** - Everything is self-contained in a single binary; no calls to external tools or special dir structures


### Workspace Crates

mbr is a Cargo workspace, and **the crate graph is the layering**: a crate can only name what it depends on, so the compiler, not a convention, keeps the render core free of the server, the server free of the GUI, and the QuickLook staticlib free of all of it. The graph is acyclic: `mbr-core` ← `mbr-server`, `mbr-ssg`, `mbr-ffi` ← the root package.

| Crate (lib name) | Path | Modules | Key deps | Never depends on |
|------------------|------|---------|----------|------------------|
| `mbr-core` (`mbr_core`) | `crates/mbr-core` | markdown, frontmatter, html, templates, config, assets, agenda, embedded_*, url_helpers, url_path, change_event, media, attrs, audio, vid, chat, contact, relationships, tasks, task_query, task_index, flashcards, wikilink(_index), tag_index, link_index, link_transform, outside_link, page_context, page_errors, readability, sorting, cache, constants, edit_auth, oembed(_cache), vault, repo, path_resolver, search, date_expr, errors; `media-metadata` feature: pdf_metadata, video_metadata(_cache), video_transcode(_cache), video_remux. Owns `templates/` (the `include_bytes!`'d assets, incl. the vite output `templates/components-js/`) | pulldown-cmark, tera, figment, papaya, rayon, reqwest+rustls, grep-*, argon2/sha2; ffmpeg/pdfium/metadata only under `media-metadata` | axum, notify, clap, pagefind, wry, uniffi |
| `mbr-server` (`mbr_server`) | `crates/mbr-server` | server, live (`LiveServer`), errors (`ServerError`), file_write, link_grep, link_rewrite; `watcher` feature: watcher (`WatcherError`) | axum, tower(-http), futures-util, tracing-subscriber, arc-swap; notify under `watcher` | clap, wry, pagefind, uniffi |
| `mbr-ssg` (`mbr_ssg`) | `crates/mbr-ssg` | build (`Builder`, `BuildStats`) | pagefind | axum, notify, clap, wry |
| `mbr-ffi` (`mbr_ffi`) | `crates/mbr-ffi` | quicklook, `mbr.udl`, the UniFFI `build.rs`; `mobile` feature: `mobile/` (the iOS core, see [Mobile core](#mobile-core-mbr-ffi-mobile)). `crate-type = ["lib", "staticlib"]` → **`libmbr_ffi.a`**, linked `-lmbr_ffi`. QuickLook compiles to nothing on non-Apple targets; `mobile` compiles (and is tested) everywhere, its UniFFI attributes being `cfg_attr(target_vendor = "apple", …)` | uniffi (Apple only; runtime + `build`, never `cli`); under `mobile`: mbr-server (no `watcher`, no `media-metadata`), axum, tower, rayon, sha2 | ssg, clap; server only under `mobile` |
| `mbr-markdown-browser` (`mbr`) | `.` | main, cli, browser, external_open, open_picker, macos_open, launch_url, errors (`BrowserError`, `ExternalOpenError`); the `mbr` and `uniffi-bindgen` bins; `lib.rs` re-exports every member at its pre-split path (`mbr::markdown`, `mbr::server`, `mbr::build`, `mbr::errors::ServerError`, …) for `tests/` and `benches/` | everything | — |

Rules that follow from it:
- **Cross-crate errors are type-erased in core.** `MbrError::Server`/`MbrError::Browser` (and `MbrError::Http`) hold an `UpstreamError` (`Box<dyn Error + Send + Sync>`); the crate owning the concrete type writes the `From` impl (`mbr_server::errors`, the root `errors.rs`), so `?` and the messages are unchanged and `downcast_ref` recovers the type. `From<http::Error>` lives in core because the orphan rule forbids it anywhere else (`http` is already in core's graph via reqwest). There is no `MbrError::Watcher`: nothing converted into it.
- Something a higher crate needs from core must be `pub`, not `pub(crate)` (e.g. `relationships::normalize_name`, `url_path::url_scheme`), and a test helper it calls cannot be `#[cfg(test)]` in core (core's `cfg(test)` is off when another crate's tests build).
- Doc links from core to higher crates are plain text (`mbr_server::watcher`), never `[`crate::…`]`.
- Version and metadata are `[workspace.package]` in the root `Cargo.toml` (listed **first**, because `scripts/bump-version.sh` and release.yml read the first `^version = ` line); internal crates are pinned `=X.Y.Z` in `[workspace.dependencies]`, which bump-version.sh rewrites too. `cargo publish --workspace` (release.yml) publishes all five in dependency order.
- Integration tests and benches stay at the root and go through the `mbr` re-exports.
- `EnvFilter` matches targets by prefix, so the CLI's `mbr=<level>` filter (from `CARGO_CRATE_NAME`) also covers `mbr_core::…`, `mbr_server::…` and `mbr_ssg::…`.

### Cargo Features

Subsystems are features of the root package, each forwarding to the crate that implements it, so non-desktop builds leave them out. `default` lists every one of them and is the shipped desktop app. With `--no-default-features` the root library is the **render core** (`mbr-core`) re-exported.

| Feature | Forwards to / optional deps | Modules / effect | Implies |
|---------|------------------------------|------------------|---------|
| `server` | `mbr-server` | `server.rs`; `ServerError` | |
| `watcher` | `mbr-server/watcher` (notify) | `watcher.rs`. Without it the server still creates the change channel (`change_event::BROADCAST_CAPACITY`) and announces its own writes on it — only events from disk are missing (`spawn_file_watcher` is the one cfg'd call) | |
| `ssg` | `mbr-ssg` (pagefind) | `build.rs` (`Builder`, `BuildStats`) | |
| `cli` | clap, rpassword, tracing-subscriber | `cli.rs`; the `mbr` bin has `required-features = ["cli"]` | `server`, `ssg` |
| `gui` | wry, tao, muda, rfd, image, objc2-*, windows-sys, gio, gtk | `browser.rs`, `external_open.rs`, `open_picker.rs`, `macos_open.rs` | `server` |
| `media-metadata` | `mbr-core/media-metadata`, `mbr-server?/media-metadata`; ffmpeg-next (log level in `main.rs`) | `video_*`, `pdf_metadata.rs` (in core: the repo scan reads media metadata) | |
| `ffmpeg-static` | `mbr-core/ffmpeg-static` | statically linked ffmpeg | |
| `ffi` | `mbr-ffi`; uniffi with `cli` (Apple only) | re-exports `mbr::quicklook`; the `uniffi-bindgen` bin. The QuickLook staticlib itself is `cargo build -p mbr-ffi --lib`, which builds no clap | |

Member crates' own features: `mbr-core`: `media-metadata`, `ffmpeg-static`; `mbr-server`: `watcher`, `media-metadata`; `mbr-ffi`: `mobile` (off by default, so the QuickLook staticlib links no server). `mbr-ssg` has none. A plain `cargo test --workspace` does not enable `mobile`; run `cargo test -p mbr-ffi --features mobile` and `cargo clippy -p mbr-ffi --features mobile --all-targets -- -D warnings` for it. CI does: flake.nix's `.#tests` and `.#tests-minimal` (and their deps-only `cargoArtifacts`/`cargoArtifactsMinimal`) add `mobileFeature` (`mbr-ffi/mobile`), which adds no crate and changes no dependency's features. `.#tests-minimal` is the run closest to the shipped app, whose server has no `media-metadata`.

Integration tests that need a subsystem declare it with `[[test]] required-features` in Cargo.toml (`server_integration` → `server`, `build_integration` → `ssg`, `cli_integration` → `cli`); a test that needs disk events is `#[cfg(feature = "watcher")]`. Shared helpers go in a neutral core module (`page_context`, `url_helpers`, `change_event`, `assets`). Windows ships `gui,server,watcher,ssg,cli` (no `media-metadata`): that string is `minimalFeatures` in flake.nix and is repeated in ci.yml/release.yml's Windows jobs, so change them together.

**iOS check** (not in CI): `cargo check -p mbr-ffi --features mobile --lib --target aarch64-apple-ios-sim` (and `aarch64-apple-ios`); the app's staticlib is the same with `build --release`, and its Swift bindings are generated from that library (see [Mobile core](#mobile-core-mbr-ffi-mobile)). Clippy for the iOS targets is not available in the dev shell (its `clippy-driver` belongs to the cached toolchain, which has no iOS std); clippy the `mobile` feature on the host. `uniffi` is gated `target_vendor = "apple"`, so it resolves for iOS. This needs the iOS std in the toolchain (`aarch64-apple-ios[-sim]` in flake.nix's `rustToolchainDev`, never in `rust-toolchain.toml`) and a *target-side* redirect to Xcode's iPhoneSimulator SDK: an `xcrun` shim running `/usr/bin/xcrun` with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, a target `clang` wrapper that unsets `MACOSX_DEPLOYMENT_TARGET` and sets `SDKROOT`, used as `CC_aarch64_apple_ios_sim` and `CARGO_TARGET_AARCH64_APPLE_IOS_SIM_LINKER`, `AR_…=/usr/bin/ar`, `IPHONEOS_DEPLOYMENT_TARGET=26.0`, and `RUSTFLAGS` unset. Never export Xcode's `DEVELOPER_DIR`/`SDKROOT` globally: that breaks nix's host linker for build scripts.

## Benchmarks

Criterion benchmarks measure performance of the critical rendering pipeline and supporting modules. They live in the root package's `benches/` and reach `mbr-core` through the `mbr` re-exports, so every benched call is cross-crate exactly as it was when the bench was its own crate. Use `--no-default-features` to avoid requiring GUI/media-metadata system dependencies.

```bash
# Compile benchmarks (fast check, no execution)
cargo bench --no-default-features --no-run

# Run all Rust benchmarks
cargo bench --no-default-features --benches

# Run a single benchmark suite
cargo bench --no-default-features --bench markdown_render

# Save baseline for future comparison
cargo bench --no-default-features --benches -- --save-baseline v0.4.2

# Compare against a saved baseline
cargo bench --no-default-features --benches -- --baseline v0.4.2

# Run frontend benchmarks
cd components && bun run bench
```

## Frontend Components

The `components/` directory contains Lit web components (TypeScript) compiled to standalone JS modules embedded into the Rust binary:

```bash
cd components
bun install        # NOT npm
bun run dev        # Development server
bun run build      # Production build (tsc + vite)
```

Built components are written to `crates/mbr-core/templates/components-js/` (gitignored; every vite config's `outDir`) and compiled into the binary via `include_bytes!`.

After a layout or `theme.css` change, `components/scripts/check-overflow.sh <server-url>` (needs `agent-browser`, `curl`, `jq`; not in CI) reports every page that scrolls sideways, at 2400/1280/1024/768/390px in light and dark; `components/src/overflow.test.ts` pins the rules it found. See `docs/reference/development.md`.

### Storage: the Vault seam

Everything that reads or writes the **repository** goes through `mbr_core::vault::Vault`, so a non-filesystem backend (an iOS coordinated vault, Android SAF, an encrypted-sync library, a test's `MemVault`) needs no change in the core. Rules:

- **No platform `cfg` in core** — no `#[cfg(target_os = "ios"/"android")]`. Platform behaviour is injected by implementing `Vault` in the platform crate (`mbr-ffi`).
- **Bulk-first.** `list_dir` is per directory and returns full `Entry`s, so a foreign vault is crossed once per directory, never per file; the scan keeps rayon per directory level.
- **`local_path` fast path, always with a fallback.** Where a real path exists, hot consumers use it: grep `search_path` (else `search_slice` on vault bytes), the task scan's buffer-reusing read (else `stat` + `read`), `ServeFile` (else `vault_body`'s ranged stream), ffmpeg/pdfium probes (else skipped), lopdf (else `load_mem`), the move's permission-preserving replace (else `write_atomic` + `remove_file`).
- **Containment at the boundary.** A `VaultPath` cannot escape lexically; symlinks are judged by `Vault::canonicalize` / `resolve_under` exactly where the desktop canonicalized before (request resolution, write targets, folder descent) — never per read, because the scanner reads every file.
- **Keys.** Indexes stay keyed by `vault.key(path)` (canonical path for `LocalVault`, so nothing downstream changed); turn a key back into a `VaultPath` with `vault.vault_path(key)` / `Repo::locate`, never open it.
- **Symlink mounts.** A link inside the repository's vault or the external overlay's whose canonical target is outside that vault is a **read-only mount** (`vault/mount.rs`), when the vault was built with `LocalVault::with_mounts` (only `Repo::init` does — QuickLook, the link tools' tests and `LocalVault::new` keep "a link out is `OutsideRoot`"). It is addressed at the link: the vault path of `<target>/x` is `<link's canonical parent>/<link name>/x`, so keys, URLs and `raw_path`s are what a real folder there would give, and nothing downstream knows. Discovery is **lazy, on `canonicalize`'s `OutsideRoot` path only** (`MountTable::resolve` finds the first prefix that leaves and judges that link), so a repository without links out pays nothing — not a syscall per file, not a pre-scan, not a lock on the success path. `map` picks the **longest** target prefix, which is what makes a nested mount win and a cycle or second link map back to the first location (each target walked once). Refusals are `external_folder_refusal` plus "cannot be read", logged once per link at WARN, and come back as plain `OutsideRoot` — never a new error kind, because `resolve_under`'s fall-through on any *other* error would hand back the unresolved link (see its doc). Accepted mounts log `Serving external folder <target> via <link> (read-only)` at INFO. **Kill switch:** `--no-symlink-mounts` / `MBR_NO_SYMLINK_MOUNTS` set `Config::no_symlink_mounts`, a `#[serde(skip)]` field like `explicit_hidden_dirs` — negative because a skipped field deserializes to `false` (= mounts on), and skipped so neither `config.toml` nor figment's `MBR_*` layer can reach it; `Config::read` reads the env var itself (`no_symlink_mounts_from_env`, fail-closed on unknown values) plus the process-wide flag main sets before any read (`disable_symlink_mounts_for_process` — the GUI re-reads config for every folder it opens without seeing argv). `Repo::with_symlink_mounts(false)` (applied by `init_from_config` and `Server::init` via `ServerConfig::symlink_mounts`) swaps both vaults for plain `LocalVault::new`s on the same roots, i.e. exactly #339's behaviour, and logs one INFO line. **Writes:** every `LocalVault` write first canonicalizes the deepest existing ancestor (`check_writable`), so a write into a mount is `ReadOnly` however it is spelled and a write through a refused link is `OutsideRoot` — the vault's own guarantee, beneath the server's `refuse_read_only` (403) checks. `link_rewrite` skips read-only files rather than failing a move. Path-based checks outside the vault (`is_within_served_roots`, `validate_media_path_with_mounts`, `resolve_media_source_file`) accept canonical paths under `Repo::mounts()` targets via `within_mount_targets`, hidden segments refused.
- **Hidden files are never served or published.** Any `.`-segment (except `.well-known`, RFC 8615) 404s from the resolver — repository, overlay and mounts — and the build never places one. Rationale: dot paths are where a repository keeps credentials and tooling state (`.env`, `.git/config` with a remote token, `.mbr/config.toml` with the edit-token hash); the scanner never indexed them but the server used to serve them by name. `/.mbr/*` is unaffected because it is routes (assets with an extension allowlist), not vault files. The exemption is `Config::explicit_hidden_dirs`, carried to the resolver as `Repo::exempt_hidden_dirs()`.

Through the vault: `repo` (scan, invalidation, basic metadata, text extraction), `path_resolver`, content `search`, `task_index`, the `markdown::*_from_vault` render/read entry points (server page render, links.json, errors.json, backlink index, static build input), every `mbr-server` write handler (`/.mbr/raw`, `edit`, `task`, `flashcard-review`, `create`, `mkdir`, `upload`, `move`), the pre-scan directory listing, and `link_grep`/`link_rewrite` (one `walk_files`-based walk). Deliberately still `std::fs`: `.mbr/` templates and `/.mbr/*` assets, the static build's *output*, PDF/video sidecars and media probes, `is_within_served_roots` (an independent second gate before `ServeFile`), QuickLook and the CLI's single-file mode, and the watcher (desktop-only notify; its canonical event paths are `LocalVault` keys by construction, pinned by a test).

### Request Flow

1. Server receives URL request
2. `path_resolver::resolve_request_path()` determines resource type, through the repository's vault
3. Returns `ResolvedPath::MarkdownFile`, `StaticFile`, `DirectoryListing`, or `NotFound`
4. For markdown: parses with pulldown-cmark, extracts YAML frontmatter
5. Renders through Tera templates from `.mbr/` or compiled-in defaults
6. Serves with embedded CSS/JS from `/.mbr/*` paths

### Configuration Hierarchy

Lowest precedence first (later layers win):

1. Compiled-in defaults (config.rs `Default` impl)
2. `.mbr/config.toml` in the markdown root
3. Environment variables (`MBR_*` prefix)
4. Command-line flags

The `MBR_*` layer splits on `__` for nested tables (`MBR_SLIDES__TRANSITION`
= `[slides] transition`).

A running server re-reads all four layers when `.mbr/config.toml` changes or on the GUI's Cmd/Ctrl+R (`mbr_server::live`), so flags keep winning; `host`/`port`/`gui_menu_bar`/the root need a relaunch.

Environment variables deliberately override `.mbr/config.toml`, because the
config file ships inside the markdown repository and the operator serving it may
not be its author.

The root directory is found by searching upward for common repository markers:
- **Directories** (in order): `.mbr/`, `.git/`, `.zk/`, `.obsidian/`
- **Files** (if no dirs found): `book.toml`, `mkdocs.yml`, `docusaurus.config.js`

`config::explicit_hidden_dirs` is the counterpart to `find_root_dir`, and exists
because the two disagree by design. Root discovery walks *upward*, so `mbr -s
.scratch` roots at the enclosing checkout — and the scanner's leading-dot rule
then skipped `.scratch`, indexing the whole repo except the folder that was
asked for (with `/.scratch/alpha/` still serving 200, because `path_resolver`
hits the disk and only the *index* was blind). The function returns the hidden
directories on the chain from the root down to the CLI target, root-relative and
purely lexically — no `is_dir` probe, so it is testable without a filesystem.
`Config::explicit_hidden_dirs` carries them; it is the one `#[serde(skip)]` field
besides `root_dir`'s reassignment, because a repository's own `config.toml` must
not be able to nominate which of its hidden directories an operator's scan walks
into. `Config::read` fills it beside `root_dir` — the only place holding both
halves — so QuickLook and the server derive it identically. Consumers rebase once
at construction (`Repo::with_explicit_hidden_dirs` joins onto `canonical_root`;
the watcher keeps the repo-relative form its callback already compares in).

The `static_folder` config option (default: `"static"`) creates a URL overlay - files in `static/images/` become available at `/images/`. It may also point *outside* the markdown root, up to two levels above it (`../static` for `project/content` + `project/static`; `../../static` for SvelteKit's `src/routes` + `static`). `config::resolve_static_overlay` is the single statement of that policy — the validator and the repo scanner share the one call so they cannot drift — and it refuses anything past the two-level budget, anything reached through `$HOME` or the filesystem root, any directory that *contains* the root, and any hidden directory (`../.git`). The last two (and the `$HOME`/root rules) are `config::external_folder_refusal`, the policy symlink mounts answer to as well.

### Key Endpoints

- `/{path}/` - Markdown files rendered to HTML (trailing slash convention)
- `/{path}` - **301 to the canonical `/{path}/`** when the path names a markdown page (also `/{path}.md` and `/{dir}` for a dir with an index file). The trailing slash decides the browser's base for the page's *own* relative links, so serving in place at a slashless URL breaks every link on the page it just served — one click later. Query string preserved; fragment left to the client per RFC 9110 §10.2.2. Static files, directory listings and `/.mbr/*` are never redirected. See `path_resolver::canonical_page_redirect`
- `/.mbr/outside/?path=…` - Where a link out of the repository leads (`outside_link.rs`); the server never inspects `path`. Also a static-build page
- `/.mbr/site.json` - Full site index with all files and frontmatter (plus each dated note's `calendar` object, see `calendar.rs`)
- `/.mbr/*` - Static assets (theme.css, components)
- `POST /.mbr/search` - Metadata + content search. Optional `today` (`YYYY-MM-DD`, the reader's date; malformed → ignored, server `Local` used) — the browser always sends it. **Date facets** (`date:` note date, `created:`, `modified:`, `when:` = date OR modified; key case-insensitive) take a `date_expr` value; a value that is not an expression stays the old substring frontmatter facet. `search.rs`'s `FacetFilter` splits the facets **once per query** (date ranges resolved, `InstantRange`s computed) and every candidate set (metadata, content, other files) goes through it; a timestamp is converted to a date only once it matched. Results gain `matched_date: {date, field}` (first date facet; omitted otherwise); a date facet with no free text sorts by that date, newest first, URL tie-break (`sort_results`); tag pages drop out (no date); other files match `created:`/`modified:` on their own times and `date:`/`when:` on mtime, and a facet-only query reaches them only when every facet is a date facet. The handler calls `SearchEngine::search_with_other_paths`, which adds the path-only `search_other_files` merge for a non-markdown `filetype` — and skips it for a date query (it ignores dates and re-sorts by score), decided from the engine's own `FacetFilter`, so the server parses nothing; `matched_date` is passed into the result builders rather than restamped
- `POST /.mbr/tasks` - Task query: filter, group, and count markdown tasks. Server/GUI only, gated on `tasks_enabled` (404 when off). Optional `today` (`YYYY-MM-DD`, the reader's date; read by `search.rs`'s `lenient_date`, so malformed → ignored, server `Local` used) decides overdue/today/tomorrow in every mode (calendar buckets, `due` filter, grid `overdue`/`overdue_before_range`/default `from`); the tasks panel and `calendar/task-markers.ts` always send `todayKey()`. In `mode: "grid"` `limit` is shared across the days by `task_query::spread_limit` (water-filling), never spent in date order; the panel draws a day's dropped rows as "+N more" (`task-grid.ts`'s `gridHiddenCount`, against the statuses on screen, fed to the grid as `DayMarks.hidden`). The `include` field (`all` default / `tasks` / `markers`) selects checkbox tasks, `TODO:`-style incomplete markers, or both; markers are additionally gated on `mark_incomplete`, since the `#mbr-marker-{line}` anchor a hit deep-links to is emitted by the highlighting pass. **`mode: "grid"`** (+ inclusive `from`/`to`, ≤ `MAX_GRID_DAYS` = 62, clamped by `grid_range`, echoed back) answers with a `TaskGridResponse` instead of `groups`: `days` (`YYYY-MM-DD` → `{tasks, open, done, overdue}`), `undated_in_day_notes`, `overdue_before_range`, `folders`, `total_matches`… (wire format in `docs/reference/http-api.md`). The handler passes the memoized `periodic_index()` (`None` while it is unavailable) to `run_grid_query`; both modes go through `Server::respond_with_task_query` (spawn_blocking, panic → 500, `scan_in_progress`, log, serialize) via the `TaskQueryOutcome` trait. The list modes' wire shape is unchanged (pinned by `test_tasks_endpoint_grid_mode_places_tasks_on_days`)
- **Per-request `edit_enabled`**: markdown pages *and directory listings/home* (`directory_to_html` takes it, so the new-note action works there) render `edit_enabled` (→ `window.__MBR_CONFIG__.editEnabled`, the editor button, task toggles, flashcard writer) from `Server::page_edit_enabled` = `config.edit_enabled && host_may_edit`, where `host_may_edit` (token configured, or `host_header_is_allowed`) is the same predicate `check_edit_access` uses for its Host gate. A page behind `tailscale serve`/a proxy without a token therefore renders read-only instead of offering writes that would all 403
- `POST /.mbr/task` - Single-line task toggle (`{path, line, expected, to}`). Gated on `edit_enabled` + `check_edit_access`, **not** on `tasks_enabled`, since in-document checkboxes exist whether or not the task browser does. Per-line optimistic concurrency: `expected` must still match the line on disk (409 otherwise). **Plus an optional whole-file `base_hash`** (the one fingerprint, `edit_auth::content_hash`, checked by `Server::base_hash_conflict` under the write lock, shared with `/.mbr/edit`): `expected` alone let a page rendered before lines were added above a task toggle a *different*, identical-looking task. A server page render reads its source with `markdown::read_source_fingerprinted` and puts the hash in `window.frontmatter.markdown_source_hash`; `/.mbr/raw` reports it in `X-MBR-Content-Hash`; a success returns the new `hash`. `task-toggle.ts` checks the page's own note's first raw read against the rendered hash (mismatch → 409-style conflict, nothing sent), sends `base_hash` on every write, records each answered hash (`noteSourceHash`), and serializes writes per file (`serializeWrite`, shared with the flashcard writer) so two quick clicks chain versions instead of the second 409ing. Other files (the task panel's) trust their first read, then chain. Absent `base_hash` = line check only. Maintains the `@done(...)` stamp per `tasks_stamp_done` **Resolution is retried** (`resolve_editable_markdown_settled`, also for `/.mbr/raw`, `/.mbr/edit` and `/.mbr/flashcard-review`): it runs *before* the per-file write lock (the lock is keyed by what it returns), so it can `stat` a note while another request's atomic write renames over it, and on Windows that open fails for a moment (delete-pending → `PermissionDenied`), which the resolver reads as "absent" — a spurious 404 for a file that is there (the Windows aarch64 CI flake in `test_concurrent_task_toggles_on_one_file_both_land`). Three 20 ms retries; pinned deterministically by `embedded_storage.rs`'s `FlakyStatVault` test. **Reading is not-downloaded aware** (`read_editable_bytes`, the read step of `/.mbr/raw`, `/.mbr/edit`, `/.mbr/task`, `/.mbr/flashcard-review`): a note the vault reports `NotDownloaded` (by `availability` or a read failing that way — on iOS, a note edited on another device goes dataless until iCloud fetches it) is `request_download`ed and polled for `MBR_ASSET_DOWNLOAD_WAIT`, then read, else `503` + `Retry-After` (DEBUG) — never the `404` "File not found" it used to be. The client side is `components/src/stale-note.ts`: `409`, a `404` from `/.mbr/raw` and a line past EOF mean "changed somewhere else" (`offerReload` → `confirm` → `location.reload()` in the document and the flashcard deck; the task panel re-queries instead; the editor only says so, since a reload would drop its edits), `503` means "still downloading, try again"
- `POST /.mbr/flashcard-review` - Append one review to a flashcard's history (`{path, line, expected, rating, at}`, `line` = the term's `<dt>` `data-mbr-line`). Same gate, `expected` guard, optional `base_hash`, atomic write, broadcast and task-index invalidation as `/.mbr/task` (the shared `read_markdown_source`/`announce_in_place_edit`). **`at` is the reviewer's local wall-clock time (`YYYY-MM-DD HH:MM`) and is what gets written** — entries have no offset and `history.ts` replays them as browser-local, so a server stamp in another zone broke FSRS's 1m/10m steps. `flashcards::parse_review_time` holds it to the exact shape (byte check first; chrono alone accepts `2026-1-6 9:05`) and to ±26 h of the server's UTC clock; missing/malformed/implausible is 422. Returns `{entry, line, inserted_at, inserted, hash}`. Unlike a toggle it **inserts** lines, so every line number below moves — see `flashcards/dom.ts::shiftSourceLines`

- `task-toggle.ts` - The one implementation of `POST /.mbr/task` (main bundle; injected into the panel as a property because it is stateful). Also owns the **live-reload seam**: **every** task write registers itself, and `wasSelfWrite()` makes `<mbr-live-reload>` skip events for that file for a short window. Suppression is not optional: the edit token lives only in memory, so a reload per checkbox would 401 the next click on a token-protected server. **The window alone is not enough**: the watcher's echo is at FSEvents' mercy — measured 1.0–4.6 s after the request on an idle macOS `/tmp`, sometimes coalesced minutes later — and an echo after the window reloaded the page (closing a flashcard deck mid-review; this predates the deck). The old mermaid-based `<mbr-relationships>` element has been removed. **Deck settings** (`slide-settings.ts`, pure): `deckSettings(config, page)` validates `__MBR_CONFIG__.slides` and `.slidesPage` and merges them, key by key, over `DEFAULT_SLIDE_SETTINGS` (= the old hardcoded `transition: 'slide'`, `controls`, `progress`); `revealConfig(settings, fixed)` maps snake_case to Reveal's camelCase and spreads mbr's fixed settings (`hash`, `history`, `center`, `scrollActivationWidth`, `keyboardCondition`, plugins) **last**, so nothing overrides them; `applyDefaultBackground` sets `data-background-image` (+ size/opacity) on each top-level `<section>` with no `data-background*` of its own, after `_transformDom`. `frontmatter/fields.ts` offers a `slides` map on decks (`isSlideDeck`), its enums `closed` (a value outside them gets a hint). `<mbr-slides>` deep-clones the top-level sections into the deck, skipping the **first** one when `isSkippableLeadingSection` says it is the empty `<section>` a leading plain `---` leaves (only whitespace/comments, no attribute but `data-mbr-*`; never a lone section, never a later empty one, which is an authored blank slide) — the renderer keeps that rule because on the page it is visible. It deep-clones, so Play awaits `mbr-mermaid.ts`'s `mermaidSettled()` and `mbr-katex.ts`'s `mathSettled()` together under one bound (`dynamic-loader.ts`'s `withTimeout`, 8 s) before cloning; the flashcard deck, which clones and caches card faces, awaits `mathSettled()` the same way (alongside its chunk import) before appending the deck, and mermaid's print re-render finds diagrams by `data-mbr-mermaid` rather than by reference; Reveal is initialized with `scrollActivationWidth: null`, since its default (435px) puts every upright phone in a scroll view that restructures the slides, and with `keyboardCondition: !isInputTarget(e) && !isModalOpen()`: Reveal's own field check reads `document.activeElement`, which is the shadow *host* for the review form's textarea, so `g` (jump to slide), Space and the arrows were stolen from it. **While a deck plays the keyboard is Reveal's**: `mbr-keys.ts::isPresentationPlaying()` (`body.slides-container`, set the moment Play starts) makes `<mbr-keys>` return before handling anything (so `?` is Reveal's help, which lists `q`), and gates `isPlayKey`, `-`/F2, Ctrl+K, Ctrl+G, `t` and `e`; `r`/`R` stay (review notes on slides are a feature). **Slide hash = playing**: a slides page loaded with a Reveal hash (`isSlideHash`: `#/2`, `#/2/1`, `#/intro`) auto-starts, so a live reload or manual reload returns to the same slide; Reveal writes no hash on the first slide, so `_keepFirstSlideHash` writes `#/0` there (after each slide change and again after Reveal's 1 s deferred-write window). **Fitting** (`slide-fit.ts`, main bundle): on `ready`/`slidechanged`/`resize` and on any `load`/`loadedmetadata` inside the deck (capture phase), the current slide is fitted — images capped to the height the text leaves (≥ `MIN_IMAGE_SHARE`), then a binary-searched font scale on the section (≥ `MIN_FONT_SCALE`), then `Reveal.layout()` to re-centre; `scrollable-slide` only when even that fails. Measuring is split from the search (`largestFittingScale`) for tests. The transform also drops `loading="lazy"` from the clones (a lazy image on a hidden slide loads after Reveal centred the slide without it) and `groupKanbanColumns` wraps a `.kanban` slide's children into `.mbr-kanban-board > .mbr-kanban-column` (a column ends after each top-level list, as the page's multicol breaks; `aside.notes` stays put), laid out as flex columns in `reveal-slides.css`. While playing, `reveal-slides.css` sets `--mbr-fab-stack-offset: 7.5rem` on `body.slides-container` (Reveal's controls are px-sized; the up arrow's top is ~117px from the bottom at any width) so the review FAB clears all four arrows. `<mbr-review>` redraws its markers and wash on `SLIDES_STATE_EVENT` `playing: true` (the clones copy markers without listeners and the ranges point into the detached original).

The links are styled by theme.css (`:is(mbr-browse, mbr-browse-single) > a`, prefixed with `body` to outweigh Pico's `nav li a`, since `<mbr-browse>` sits in a header `<li>`), hidden while the element is `:not(:defined)`. Header/footer links holding an SVG get the icon-button box (36px, 40×44 on touch). Internal links: `{{ relative_root | default(value="/") | safe }}page/` — the `| safe` is required (Tera escapes the `default` literal, and escaping it again breaks the URL; pinned by `test_header_link_relative_root_idiom`). mbr's own docs override two of them (`docs/.mbr/`, GitHub links)

**Tera Template Gotchas:**
- Chained `default()` filters don't work as expected for variable fallbacks. Use conditionals instead:
  ```jinja
  {# BAD - fails if current_dir_name doesn't exist #}
  {{ title | default(value=current_dir_name) | default(value="") }}

  {# GOOD - handles missing variables properly #}
  {% if title %}{{ title }}{% elif current_dir_name %}{{ current_dir_name }}{% endif %}
  ```
- Use `{% if varname %}` to check variable existence before using
- `{{ frontmatter_json | safe }}` outputs frontmatter as JSON (excludes rendered markdown for efficiency)
- `server_mode` is a boolean template variable: `true` in server/GUI mode, `false` in static builds. Use it to conditionally include live-only features (e.g., `{% if server_mode %}<mbr-live-reload>{% endif %}`)

### Oembed System

The oembed system auto-embeds bare URLs in markdown with rich previews:

**Supported URL types:**
- **YouTube** - Embedded player (no network call needed)

- `oembed.rs` - URL detection and embed generation

### Markdown Extensions

**Section Attributes:**
When `enable_sections` is active, horizontal rules create `<section>` elements. Add attributes to the following section:
```markdown
--- {#intro .highlight data-transition="slide"}

Content in section with id="intro" class="highlight" data-transition="slide"
```

Attribute syntax (modelled on pulldown-cmark's heading attrs, but section values may be quoted, which heading attrs may not):
- `#id` - ID attribute (last one wins if multiple)
- `.class` - CSS class (multiple allowed)
- `key=value`, `key="quoted value"` or `key='quoted value'` - Custom attributes. A quoted value runs to its closing quote, so `#`/`.` inside it stay value

**Implementation:** `attrs.rs` parses the attribute block. `markdown.rs` transforms the event stream (pulldown-cmark converts `--- {attrs}` to em-dash + text paragraph). The em-dash text only *detects* the rule (`section_rule_attrs`); the `{…}` that is parsed is sliced from the **source** by the paragraph's byte range (`section_rule_source_attrs`), because smart punctuation has already rewritten the text (`--` → en dash, `'` → curly quotes), which broke values like `style="--pico-color:cyan"`. Values are therefore verbatim: no escape or entity decoding. `html.rs` applies attrs when opening sections. An attributed rule with only frontmatter/blank lines before it (`only_frontmatter`) emits no `Rule` and its attrs go to section 0, so the first `<section>` gets them (no empty first slide); a plain leading `---` is untouched. Indexing stays in one place: pass 1 counts rules, the writer counts the same `Rule` events. Reveal.js background URLs among them (`data-background-image`, `-iframe`, each `data-background-video` list item, and `data-background` only when `is_reveal_background_url` — Reveal's own image test — says it is not a colour) go through `transform_link` after pass 2 (`transform_section_background_urls`), so they resolve exactly like `![](…)` on the same page; `page_errors::validate_media_references` checks them (not `collect_media_references`, so no video probe). Heading attrs are not rewritten: Reveal reads backgrounds only from `<section>`.

**Vid Shortcode:**
Embed videos with the `{{ vid(...) }}` shortcode:
```markdown
{{ vid(path="videos/demo.mp4") }}
{{ vid(path="Eric Jones/Eric Jones - Metal 3.mp4", start="10", end="30", caption="Great performance") }}
```

The shortcode supports:
- `path` - Video path relative to `/videos/` folder (required)
- `start` / `end` - Playback timestamps (optional)
- `caption` - Figure caption (optional)

**Note:** Pulldown-cmark's smart punctuation converts `"` to curly quotes (`"` `"`), so the regex supports both straight and curly quotes.

**Page Styles and Types:**
Two frontmatter fields form the `<body>` class list: `style` (a string, a space-separated string, or an array — every entry is a class) and `type` (a single string, slugified via `markdown::slugify` then `collapse_dashes`, e.g. `Meeting Notes` → `meeting-notes`, `Book Review (2024)` → `book-review-2024`). `collapse_dashes` is applied to the class only, never inside `slugify`: `slugify` also generates heading anchor ids, whose doubled dashes (`Hello, World!` → `hello--world`) are frozen because they are live `#anchor` targets in existing repos. `Templates::render_markdown_with_tera` combines them in `body_class_list` (`crates/mbr-core/src/templates.rs`) — type first, styles after, deduped first-seen — and inserts the result as the `style` context variable, so a repo's existing `.mbr/index.html` gains the feature untouched. The `type` context variable is the authored value with surrounding whitespace trimmed (`contact::normalize_type`, run by the simplifier, so templates, `site.json`, `window.frontmatter`, search and the body class all see the same value; a blank `type` is dropped), but otherwise unslugified, because templates gate on its value (`{% if type == "person" %}`). `type` is aligned with the [OKF spec](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) and is the preferred spelling for a note's kind; `style` remains for pure presentation. Shipped styles with CSS in `templates/theme.css`: `outline`, plus `slides` (`reveal-slides.css`, triggered client-side by the body class in `mbr-slides.ts`). User docs: `docs/features/page-styles.md`. Kanban is **not** a page style: its theme.css rules expect `.kanban` on a `--- {.kanban}` `<section>` (`.kanban > ul` = cards); `style: kanban` puts it on `<body>` and breaks the page (`docs/features/kanban.md`).

### Static Site Generation

The `-b/--build` flag generates a complete static site:

```bash
mbr -b /path/to/markdown/repo              # Output to ./build
mbr -b --output ./public /path/to/repo      # Custom output directory
mbr -b --build-concurrency 8 /path/to/repo  # Explicit concurrency limit
```

**Build process:**
1. Renders all markdown files to HTML **in parallel** (uses `futures::stream::buffer_unordered`)
2. Generates section pages for directories **in parallel**
3. Symlinks assets (images, PDFs, videos) - macOS/Linux only
4. Copies `.mbr/` folder with default files
5. Creates `.mbr/site.json` with full site metadata

**Performance optimizations:**
- **Parallel rendering**: Default concurrency is 2x CPU cores (max 32). Control with `--build-concurrency`.
- **Oembed disabled by default**: Build mode sets `oembed_timeout_ms=0`. Oembed fetching is parallelized and cached, so overhead is minimal when enabled.
- To enable oembed in builds: `mbr -b --oembed-timeout-ms 500 /path/to/repo`

**Output structure:**
```
build/
├── index.html              # Home page
├── README/index.html       # /README/ → README.md
├── docs/
│   ├── index.html          # Section page
│   └── guide/index.html    # docs/guide.md
├── images/ → ../images     # Symlinked assets
└── .mbr/
    ├── site.json           # Generated site metadata
    ├── theme.css           # Default or custom
    └── *.js/*.css          # Built-in assets
```

**Note:** Asset placement is platform dependent. macOS/Linux symlink assets into the
output; Windows copies them, because `CreateSymbolicLinkW` requires Developer Mode or
elevation. The decision lives in `build::AssetPlacement::for_current_platform()` and
`Builder::place_asset()` takes the strategy as a parameter so both paths are testable
on any host.

## Linux Desktop Entry

`linux/mbr.desktop` plus `mbr-icon.png` are installed by the Nix package into
`share/applications/` and `share/icons/hicolor/256x256/apps/`. Without a desktop entry an
application launcher cannot tell `mbr` is a GUI program and runs it through a terminal,
producing a console window alongside the browser window. `Path=/` is deliberate: it makes
`main.rs::needs_folder_picker` open the folder picker rather than let `mbr`'s default path
argument (`.`) point at whatever directory the launcher happened to be in. The entry is
only visible to a launcher once mbr is on an `$XDG_DATA_DIRS` path (`nix profile install`),
not from a bare `nix build`.

## EGL on non-NixOS hosts

WebKitGTK 2.52's web process `CRASH()`es if `eglGetDisplay` returns `EGL_NO_DISPLAY`, and
no environment variable opts out (`WEBKIT_DISABLE_DMABUF_RENDERER` and
`WEBKIT_DISABLE_COMPOSITING_MODE` were both tried; the abort is upstream of either, in
`WebProcess::initializePlatformDisplayIfNeeded`). Nix's libglvnd finds vendor ICDs under
`/run/opengl-driver/...` on NixOS but nowhere usable on other distributions — the host's
`libEGL_mesa.so` cannot be loaded from a Nix process, since its `libgallium-*.so` is not
on a Nix binary's search path and is built against a different glibc. `flake.nix` therefore
**appends** nixpkgs' Mesa as a last-resort EGL vendor (`glvndVendorDefaults` /
`mesaEglVendorDir`), in both the package wrapper and the devShell. Appended, never
substituted, so a host driver still wins where there is one. Costs ~805 MiB of closure on
a host with no Mesa in its store; near-zero on NixOS.

## macOS App Bundle

The project includes a native macOS app bundle in `macos/`:
- `MBR.app/Contents/MacOS/mbr` - Binary (symlinked/copied during build)
- `MBR.app/Contents/Resources/Assets.car` - Application icon as macOS 26 draws it, a copy of `macos/Assets.car`
- `MBR.app/Contents/Resources/AppIcon.icns` - Application icon fallback, a copy of `macos/AppIcon.icns`
- `MBR.app/Contents/Info.plist` - App metadata

**App icon.** The bundle carries the icon twice, both files written by `scripts/gen-app-icons.sh` from `apple/ios/MBRMobile/AppIcon.icon`, the script that also generates that package's layers, so the Mac matches the iPhone. `macos/Assets.car` is what macOS 26 draws: actool's compiled asset catalog of the package (`--platform macosx`, deployment target = the flake's `LSMinimumSystemVersion`), found through `CFBundleIconName = AppIcon` in Info.plist (the flake's and the template's) and drawn as the layered Liquid Glass icon with its dark/clear/tinted appearances. `macos/AppIcon.icns` is the fallback, for macOS before 26 and anything reading `CFBundleIconFile`: each of the ten legacy sizes is Icon Composer's `ictool` render (`--platform macOS`, needs Xcode) at exactly that pixel size, full-bleed with ictool's own rounded corners. It is deliberately **not** inset on Apple's 824/1024 Mac grid with a shadow (the geometry actool's own fallback `.icns` uses): macOS 26 treats a legacy `.icns` as legacy artwork — one that does not fill its canvas is set on a white system squircle (the Dock showed a navy square inside a white one), and even a full-bleed one gets a thin light frame, which only the compiled catalog avoids; verified with `NSWorkspace.icon(forFile:)`, which draws what the Dock draws. `macos/AppIcon.iconset/` is the script's intermediate (the `iconutil -c icns` input), checked in beside the result. A rebuilt `Assets.car` is never byte-identical — a build `Timestamp` in its header, and a fresh temp name and digest for each of the seven bitmap renditions — so the script keeps the old file when `assetutil --info` of old and new agree once those lines are dropped (the layer SVGs' own digests, the colours and the glass properties are what is compared), and a no-op run leaves `git status` clean; delete the file to force a rebuild. The flake copies `${./macos/Assets.car}` into the bundle and sees only git-tracked files, so `git add` it after a regeneration. `scripts/build-macos-app.sh` only copies both into the template bundle (the template's `Assets.car` is gitignored; its `.icns` is checked in) and warns when either is missing or older than the script or the package; it never regenerates. The Linux `mbr-icon.png` is a separate artwork, unchanged by any of this.

The app uses **muda** crate for native menubar with standard macOS keyboard shortcuts (Cmd+Q quit, Cmd+W close window). Platform-specific code is gated with `#[cfg(target_os = "macos")]`.

The Swift shells live under `apple/`: `apple/quicklook/` is the QuickLook preview extension that ships inside `MBR.app` (built by flake.nix's `mbr-quicklook`, or by hand with `apple/quicklook/build.sh`, which needs Xcode and finds it itself for `xcodebuild`: the caller's `DEVELOPER_DIR` if it has one, else `xcode-select -p`, else `/Applications/Xcode.app` — so it runs as is in the nix dev shell, whose `DEVELOPER_DIR` is nix's apple-sdk). `apple/ios/` is the iOS/iPadOS app (`apple/ios/build.sh`; see [iOS app](#ios-app-appleios)).

## Nix Packaging

The project uses Nix flakes for reproducible builds:

```bash
# Build the binary and macOS app bundle
nix build .#mbr

# Create release archives (tar.gz for all platforms, zip for macOS)
nix run .#release

# Check flake validity
nix flake check
```

The flake builds with crane over the whole workspace: `cargoArtifacts`/`cargoArtifactsMinimal` (deps-only, `--workspace`, zstd `-19`) feed `.#clippy`/`.#tests` (`--workspace`) and `.#clippy-minimal`/`.#tests-minimal`; `.#mbr-cli` builds `-p mbr-markdown-browser`; `.#mbr-quicklook-staticlib` builds `-p mbr-ffi --lib` and installs `lib/libmbr_ffi.a`, which `.#mbr-quicklook` links `-lmbr_ffi`; `.#fmt` is `cargo fmt --all`; `.#cargo-sort` is the manifest sort check (cargo-sort only, over a fileset of the `Cargo.toml`s and `.tomlfmt.toml`).
